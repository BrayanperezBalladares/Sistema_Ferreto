# Development Workflow — Sistema Ferreto

> **Audience**: AI Coding Agents & Software Engineers
> **Workflow**: Spec-Driven Development (OpenSpec) + Test-Driven Development (TDD)

---

## 1. Golden Rules of Development

1. **Never code without explicit authorization**:
   - Small bugfixes or doc updates stay small and direct.
   - Any new functional capability or structural modification requires an OpenSpec change cycle.
2. **Never break database isolation**:
   - Automated tests run **exclusively** against the `*_test` database.
   - Development database (`ferreto`) must remain invariant throughout test execution.
3. **Never bypass validation**:
   - Every change must pass `composer test`, `composer analyse`, and `openspec validate`.

---

## 2. Step-by-Step Feature Lifecycle

```
[1. Sync & Branch]
       |
       v
[2. OpenSpec Change (if functional)] ---> proposal.md -> spec.md -> design.md -> tasks.md
       |
       v
[3. TDD Implementation] -------------> RED (failing test) -> GREEN (implementation) -> REFACTOR
       |
       v
[4. Quality Validation] -------------> composer test (382+) + composer analyse (max) + git diff --check
       |
       v
[5. Conventional Commit] ------------> type(scope): description (NO AI trailers)
       |
       v
[6. Maintainer Review] --------------> Archival via `openspec archive` -> Local branch ready for PR
```

### Step 1: Branch Creation
Always start from an up-to-date `main`:
```powershell
git checkout main
git pull origin main
git checkout -b feature/<descriptive-name>
```

### Step 2: OpenSpec Change Initialization
For substantial functional changes, initialize an OpenSpec change structure:
```
openspec/changes/<change-name>/
├── proposal.md   # Intent, problem statement, business justification, and impact
├── specs/        # Delta specifications with ADDED/MODIFIED/REMOVED requirements
│   └── <domain>/spec.md
├── design.md     # Architecture decisions, schema migrations, API contracts
└── tasks.md      # Bounded, ordered checklist of implementation tasks
```
Validate the change structure:
```powershell
openspec validate <change-name>
```

### Step 3: Test-Driven Implementation (TDD)
1. **Write failing tests first**:
   - For domain logic: create unit tests under `tests/Unit/`.
   - For HTTP endpoints: create integration tests under `tests/Integration/`.
2. **Use Test Isolation**:
   - Test classes interacting with the database must use `Tests\Support\DatabaseIsolationTrait`.
   - `setUpBeforeClass()` verifies test DB name ends in `_test`, runs migrations, and checks dev DB state.
   - `tearDownAfterClass()` verifies dev DB was not modified.
3. **Run tests via isolated environment runner**:
   ```powershell
   composer test
   # Or for a specific test file:
   vendor\bin\phpunit tests/Integration/YourTest.php
   ```

### Step 4: Full Quality Gate
Before creating any commit, run the complete suite of canonical checks:

```powershell
# 1. Automated Test Suite (All tests must pass with 0 failures and 0 errors)
composer test

# 2. Static Analysis at Level Max (0 errors allowed)
composer analyse

# 3. Whitespace & Line Ending Hygiene (No trailing whitespace, clean diff)
git diff --check

# 4. OpenSpec Specification Validation
openspec validate --specs
```

### Step 5: Git Commit Standards
- Use **Conventional Commits**:
  - `feat(inventory): add batch stock adjustment endpoint`
  - `fix(access): correct timeout check in peekUser`
  - `test(catalog): cover product search pagination`
  - `docs(ai): update architecture guide for router`
  - `style(ui): align table padding with design tokens`
  - `chore(deps): update composer dependencies`
- **STRICT PROHIBITION**:
  - **NEVER** include `Co-Authored-By: ...` trailers.
  - **NEVER** include AI generation attributions (e.g. `Generated by Claude`, `Assisted by Codex`).

### Step 6: Change Archival & Delivery
Once all tasks in `tasks.md` are completed and verified:
1. Reconcile delta specifications into canonical specs:
   ```powershell
   openspec archive <change-name> --yes
   ```
2. Verify all canonical specs remain valid:
   ```powershell
   openspec validate --specs
   ```
3. Commit the archival:
   ```powershell
   git commit -m "chore(<scope>): archive <change-name>"
   ```
4. **DO NOT PUSH OR MERGE**: Stop and present the verified local branch to the human maintainer.
